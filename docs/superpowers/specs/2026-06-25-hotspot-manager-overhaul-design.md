# Hotspot Manager Overhaul — Design (Approach C, Hybrid)

Date: 2026-06-25
Status: Approved (design); pending implementation plan

## Problem

The admin hotspot manager has three pain points:

1. **Stale catalog.** The admin reads the scene list from a static snapshot,
   `src/data/scenesManifest.json`, generated by `scripts/generate-scenes-manifest.mjs`.
   Renaming/adding/deleting a photo in `public/assets/<location>/Media/` does NOT
   update the snapshot, so renamed files can't be found in the admin until the
   script is re-run. The catalog is not "live".
2. **Heavy file search.** The target-scene picker builds a `<select>` with 264+
   `<option>` nodes and **rebuilds all of them on every keystroke**
   (`updateOptions` is the `oninput` handler in `AdminPanel.js`). Filenames are
   long and hard to scan; there is no visual preview.
3. **Lag** — felt most in (a) the form/panel (full `renderForm` rebuild incl. the
   264-option picker on every select/edit) and (b) 3D interaction
   (`GazeController` raycasts every frame even in admin mode, where the user drives
   with the mouse, not gaze).

The editor panel is also tall and list-heavy. The user wants it **compact but
fully functional and easy**.

## Goals

- Catalog is **live in dev** — file renames/adds/deletes appear without re-running
  a script.
- **Fast, visual file picking** — thumbnail grid grouped by location with
  type-ahead filter; no 264-option DOM rebuild.
- **Drag & drop upload** — drop a photo from the OS into the browser; it is saved
  into the right `Media/` folder, optimized, and thumbnailed.
- **Lower lag** — no per-frame gaze raycast in admin mode; no full-list rebuilds.
- **Compact editor** — shorter panel, all functions retained, see-all-hotspots
  chip row.

## Non-goals (YAGNI / explicitly out of scope)

- Moving hotspot persistence off `localStorage` (save-to-file was offered and not
  selected; hotspots stay in `localStorage` with the existing debounced auto-save).
- Intra-UI drag (dragging a thumbnail onto a target slot). Assignment is by
  **click**, which is simpler and equally fast. Drag is reserved for OS→browser
  file upload only.
- Any production-server file API. The admin is dev-only
  (`import.meta.env.PROD` gates it); all new file endpoints live in a Vite **dev**
  plugin and are absent from production builds.

## Architecture

```
Browser (admin, dev only)                 Vite dev server (Node)
┌─────────────────────────────┐           ┌──────────────────────────────┐
│ AdminPanel (compact editor)  │           │ admin-fs plugin               │
│  ├─ ScenePicker (thumbnails) │◀── GET ───│  /__admin/scenes  (live list) │
│  │   + type-ahead filter     │           │  POST /__admin/upload         │
│  └─ HotspotForm (compact)    │── POST ──▶│    → save + optimize + thumb  │
│ SceneCatalog (data layer)    │           └──────────────────────────────┘
│  dev: fetch /__admin/scenes  │
│  prod/fallback: manifest.json│           public/assets/<loc>/Media/*.jpg
│ PanoramaViewer (3D place)    │           public/assets/<loc>/Media/.thumbs/*.jpg
│ App.render (gaze gated)      │
└─────────────────────────────┘
```

### Components

**1. `admin-fs` Vite dev plugin** — `vite-plugins/admin-fs.js`, registered in
`vite.config.js` `plugins: []`. Uses `configureServer(server)` middleware. Active
only on the dev server; contributes nothing to `vite build`.

- `GET /__admin/scenes` → scans `public/assets/*/Media/` at request time (same
  logic as `generate-scenes-manifest.mjs`: dirs with a `Media/` subfolder, image
  files only, excluding the `.thumbs/` dir) and returns the catalog JSON
  `[{ location, count, scenes:[{ filename, path, thumb }] }]`. This is the **live**
  source of truth in dev.
- `POST /__admin/upload?location=<loc>` (body = image bytes; filename via header
  or query) → writes the file to `public/assets/<loc>/Media/<name>`, runs the
  optimize step (reuse the ffmpeg `scale=8192:-1 -q:v 3` call factored out of
  `optimize-panoramas.mjs`), generates a thumbnail, and returns the new
  `{ filename, path, thumb }`. Rejects non-image types and path traversal in the
  filename.

**2. Thumbnail pipeline** — thumbnails live in
`public/assets/<location>/Media/.thumbs/<same-filename>.jpg`, ~320px wide
(~20 KB). Two producers, one shared helper (`vite-plugins/thumb.js` →
`makeThumb(srcPath, destPath)`):
- batch: a new `scripts/generate-thumbs.mjs` walks every `Media/` folder and emits
  a thumb per photo (kept separate from `optimize-panoramas.mjs` so each script
  has one job);
- on-demand: the upload endpoint calls `makeThumb` for the new file.
The `.thumbs/` dir is excluded from the scene scan so thumbnails never appear as
selectable scenes. The picker shows `scene.thumb`; if a thumb is missing it falls
back to the full image with `loading="lazy"`.

**3. `SceneCatalog`** — `src/utils/SceneCatalog.js`, the single data layer the
admin reads instead of importing `scenesManifest.json` directly.
- `async getLocations()` → in dev, `fetch('/__admin/scenes')`; on any failure (or
  in a prod-style preview), falls back to the bundled `scenesManifest.json`.
- `async refresh()` → re-fetch (called after upload / by a manual refresh button).
- Caches the last result; exposes `flat()` for the flattened `availableScenes`
  list the form needs.

**4. `ScenePicker`** — `src/components/admin/ScenePicker.js`, a popover/modal
opened from the editor's Target button (and reused for "set first panorama" and
"jump to scene"). A thumbnail grid grouped by location with a type-ahead filter
input. **Only filtered items are rendered** (re-render the filtered subset on
input, not a 264-node rebuild), eliminating the current per-keystroke cost.
Selecting = clicking a thumbnail → returns the chosen `path` and closes. Includes
an OS file dropzone that POSTs to `/__admin/upload`, then `SceneCatalog.refresh()`
and re-renders.

**5. Compact `HotspotForm` / editor layout** — restructure the editor panel
(per the approved mockup):
- Header: scene filename + location + hotspot count + auto-save indicator
  (`✓ saved`) + close.
- Chip row: every hotspot in the scene as a small clickable chip (select/jump),
  plus an `+ add` affordance; replaces hunting in 3D.
- Compact form for the selected hotspot: label input; type select; **Target as a
  button** that opens `ScenePicker` (replaces the inline 264-option `<select>`);
  Size/Text/Offset as a tight 3-row `label · slider · value` grid; color as a
  compact swatch row; `Wrap label` checkbox; `Advanced` (custom icon URL) collapsed
  by default; delete button.
- Footer: "right-click panorama to add · auto-saves".
Field edits update in place and call the existing `markDirty()` (debounced
auto-save) — no full `renderForm` rebuild on each keystroke.

### Performance fixes

- **Gate gaze in admin.** In `App.render` (`src/main.js`), skip
  `gazeController.update()` when `panoramaViewer.isAdminMode` is true. Removes the
  per-frame recursive raycast against the scene while editing.
- **No full-list rebuilds.** The 264-option `<select>` and its per-keystroke
  `updateOptions` are removed; `ScenePicker` renders only filtered thumbnails.
- **In-place form updates.** Selecting/editing a hotspot updates existing fields
  rather than tearing down and rebuilding the whole form DOM.

## Data flow

1. Admin opens → `SceneCatalog.getLocations()` (dev: live `GET /__admin/scenes`).
2. User edits a hotspot → field change → `markDirty()` → debounced
   `AdminPersistence.saveHotspots(...)` to `localStorage` (unchanged, already
   working).
3. User clicks Target → `ScenePicker` opens with live thumbnails → click sets the
   hotspot's `target` → `markDirty()`.
4. User drops a photo → `POST /__admin/upload` → saved+optimized+thumbed →
   `SceneCatalog.refresh()` → picker shows the new scene immediately.

## Error handling & fallbacks

- `SceneCatalog` falls back to `scenesManifest.json` if the dev endpoint is
  unreachable (e.g. production preview), so the admin never hard-fails.
- Upload endpoint validates content-type (image only) and sanitizes the filename
  (reject `/`, `\`, `..`); returns 4xx with a message the picker shows as a toast.
- If `ffmpeg`/thumb generation fails on upload, the original file is still saved
  and the picker falls back to the full image for preview; a toast reports the
  thumb failure.
- The static `scenesManifest.json` + its generator are **kept** (production
  fallback). A short note in `CLAUDE.md` documents that the manifest is the
  prod/offline snapshot while `/__admin/scenes` is the dev live source.

## Verification

- **Live catalog:** rename a file in `Media/`, click refresh in the picker → new
  name appears, old gone, no script run.
- **Search perf:** typing in the picker filter is smooth with 264 scenes (only
  filtered thumbs rendered).
- **Drag & drop:** drop a JPG → appears in the grid with a thumbnail; file exists
  in the correct `Media/` folder; selectable as a target.
- **Gaze gating:** in admin mode, confirm gaze raycast no longer runs each frame
  (3D drag is smooth); outside admin, gaze still works.
- **Auto-save round-trip:** add/edit/drag/delete → reload scene → hotspots persist
  (existing behavior preserved).
- **Prod build:** `npm run build` succeeds and the bundle contains no `/__admin/*`
  calls / dev plugin (admin tree-shaken in prod).
